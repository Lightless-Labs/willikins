# Error JSON uniformity gaps found by the task 1a and 1b verifiers

Task 1a gave `CheckError`, `CheckWarning`, `PlanError` and `DocumentErrorKind` a `kind` tag and
`Reported<T>` adds `message`. Four places still fall short of "one JSON object shape", all
found by the verifiers and deliberately left for the task that owns them:

1. `InputError` (a `describe` failure's error object) carries neither `kind` nor `message`;
   `willikins --json describe` on a bad input emits `{input, error: {type_name, reason}}`.
   The MCP `describe` tool (task 10a/10b) must decide whether it is an error at all or a
   result field, and pin it either way.
2. `DocumentErrorKind`'s two variants each declare their own `message` field, and that field
   is not the Display (Display prefixes `line:column: ` or `path: `). `Reported` cannot wrap
   it without a silent key collision. Either rename the inner field or give `DocumentError`
   its own `{kind, message, line, column, path}` serialization, in task 10a when the
   `validate` tool's result shape is fixed.
3. `crates/willikins-cli/src/render.rs` keeps a hand-maintained 21-arm
   `check_error_variant_name` for the text renderer that must agree with the serde tag.
   Fold it: derive the leading token from the serialized `kind` (or expose a `kind()` on the
   enum generated by the same `variant_kinds!` list).
4. The `propose-slug` path still emits hand-built `{"error": ...}` and `{type_name, reason}`
   JSON for `ProposeError` and `ParseError`. Outside the milestone 2 MCP surface; align when
   `propose_slug` becomes an MCP tool (task 10b).

Naming questions from the task 1d verifier, for task 1e or 10a to settle:

- `Plan.workflow` is document-authored text published as `workflow`, not `document_name`
  as trust boundary 4's wording suggests; `MissingInput.default` is document-authored and
  not named `document_*` (always `None` today).
- `Description.resolved` and every `Plan` value mix document defaults and literals with
  caller-supplied values without provenance. Values-as-values is the plan's intent; record
  the decision.
- No snapshot pins `describe`'s JSON field names; the `Description` schema snapshot from
  task 1a should be checked to carry `document_description`.
